# 방향 — 로컬 SLM 메일 비서 (몰두봇 메일 도메인)

2026-08-18. `local-slm` PoC 결과와 `docs/design-system` 을 바탕으로 정한 방향과 그 근거.
결론부터: **"빠른 챗봇"이 아니라 "도착한 메일을 뒤에서 정리해 두고, 근거와 함께 보여주고, 쓰기 동작은 확인 뒤에만 하는 비서"** 로 간다.

## 1. 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 포지셔닝 | 도착 즉시 백그라운드 요약(Watch) + 캐시 → 볼 때는 0초 | VDI 4vCPU 에서 통당 8~20초는 물리 한계. 실시간 대화가 아니라 사전 정리로 체감 속도 해결 |
| 모델 | 기본 Qwen3.5-**4B** Q4_K_M + Watch 사전 요약, 2B 는 속도 급할 때 선택 | 2026-08-19 VDI 실메일 30통 눈 비교: 4B 가 2B 보다 확실히 낫다(사용자 판단). 4B 통당 20~30초는 도착 시 뒤에서 요약하면 체감되지 않음. Kanana 1.3B 는 슬롯 채우기 불가 |
| 추출 방식 | 통째 입력이 아니라 **정리 → 관련 문장 추리기 → JSON 스키마 강제 → 후처리 검증** | 정확도의 절반은 모델 밖에서 나왔다: 배너·인용 제거, 링크 자리표시, 기한 근거 검증이 오답 대부분을 잡음 |
| 화면 | 근거 문장을 항상 함께 표시, 원문 한 클릭 | 2B/4B 는 "분류·초벌"까지. 신뢰는 근거로 만든다(UX 대원칙 4) |
| 쓰기 동작 | 답장 초안은 자동, **발송은 승인 카드 → 메일 앱/회신 창에서 사용자가** | 메일 본문은 외부 텍스트 = 프롬프트 인젝션 경로. 부작용 있는 동작은 사람 뒤에 둔다 |
| Outlook 연동 | 클래식: COM/AppleScript(현재) · **새 Outlook: Office.js 추가 기능** · Graph 미사용 | 새 Outlook 은 COM 없음. 추가 기능은 클라이언트 안에서 열린 메일을 읽고 localhost 로 보낼 수 있다 |
| 파일·브라우저 | SLM 이 "무슨 동작인지"만 고르고 실행은 결정적 코드. 자유 탐색은 안 함 | 2B 급 판단은 흔들린다. 정해진 시나리오(링크 열기·첨부 저장·표 추출)만 |

## 2. 구성 (이 저장소)

```
web/pipeline.js        공용 파이프라인(JS). 정리·필터·프롬프트·스키마·검증·근거·답장 초안. 패널과 추가 기능이 공유
web/index.html + app.js  브리핑 패널 — 디자인 시스템 560 런처. 오늘 업무 → 메일 요약 → 답장 초안(승인 카드)
web/addin/             새 Outlook 추가 기능(manifest.xml + taskpane.html). 같은 pipeline.js
web/ds/                docs/design-system 토큰·킷 CSS 사본(styles.css, panel.css)
windows/Summarize-Mail.ps1  VDI 콘솔 도구. -Watch(감시·캐시) -Panel(내보내기+서버+브라우저) -Export
summarize.py / fetch_outlook.py  Mac 콘솔 도구. --panel
```

흐름: Outlook(COM/AppleScript 또는 Office.js) → 메일 JSON → **llama-server**(`--path web` 로 정적 파일도 서빙)
→ 브라우저/작업창의 pipeline.js 가 `/v1/chat/completions` 에 스키마 강제 호출 → 슬롯 → 화면.
서버는 하나, 별도 백엔드 없음. WPF 앱은 WebView2 로 `http://127.0.0.1:8080/` 을 띄우거나 pipeline.js 규칙을 C# 으로 옮긴다.

## 2b. 패널이 지금 하는 것 (2026-08-18 밤 기준)

- 오브(LED 도트 얼굴, 킷 OrbLed 그대로): 대기 idle · 요약/초안 작업 중 clock+무지개 링 · 새 메일 mail 글리프(3초) · 정리 끝 grin(2.5초) · 서버 없음 sorry. 클릭/⌥Space 로 접힘(알약)↔펼침.
- 알림 말풍선(OrbNotificationWindow 320×84): 새 메일 N통 → 요약 뒤 "할 일 N건 정리됨 · 첫 할 일". 클릭하면 오늘 업무로.
- 컴포저 = **명령 팔레트**(⌘K 스타일): 포커스/타이핑하면 명령 후보 + 캐시된 메일 즉시 검색(모델 없음), ↑↓↵·Esc, `/`로 포커스. 자유 질문은 받지 않는다("검색으로 걸러 보기"까지만).
- **대기열**: 요약·초안 등 모델 작업은 한 줄로 서서 하나씩(컴포저 옆 칩 "요약 중 · 대기 N · 약 Ns", 작업 로그에 진행/대기). 초안은 맨 앞.
- **완료 체크**: 행 호버/카드의 `완료` → 목록·추천·리포트에서 빠지고 "오늘 완료 N" 집계. **오늘 마무리** 리포트(처리한 것 · 남은 것 · 내일 기한 · 기한 없는 할 일).
- **리듬**: 첫 정리 끝나면 말풍선("메일 N통 정리됨 · 할 일 M건"), 17:30 이후 "오늘 마무리 준비됨"(클릭 → 리포트). 오브 벨 글리프.
- 오늘 업무 → 메일 요약(요점≤3+근거) → 답장 초안(작업물 패널) → 발송 전 확인 카드 → 메일 앱/회신 창.
- 오늘/이번 주 리포트: 슬롯을 모델 없이 조합. 결론 한 문단 → 지금 해야 할 일 → 다가오는 기한 → 확인만. 광고·소식지·인증 제외 건수 표기. 복사.
- 모델 토글: llama-server 라우터 모드(`--models-dir --models-max 1`) — 요청의 model 필드로 교체, 캐시는 모델별. 작업 로그(접힘)에 메일별 시간·토큰.
- 감시: `-Panel -Watch`(PS) / `--panel --watch 30`(py) 가 주기적으로 inbox.json 을 다시 쓰고, 패널이 20초마다 새 ID 만 요약한다.

## 2c. VDI 리소스 정책 (2026-08-19 결정: 실시간 아님, 최소 자원, 최대 정확도)

- **모델 전 규칙 트리아지**: 광고·소식지·인증코드·자동발송은 모델을 부르지 않고 규칙으로 분류(`pipeline.js triage`). 실제 업무 메일만 4B 로 → 호출 수 자체가 준다. (2B 가 광고에서 할 일을 과추출하던 문제도 여기서 차단)
- **배치**: 실시간 폴링 대신 5분 주기 내보내기(`-Panel -Watch`, `-WatchInterval` 로 조정) + 패널 1분 폴링, 새 메일만 요약. 요약 루프는 항상 하나(중복 호출 방지).
- **절약 모드(`-Gentle`, -Panel/-Watch 기본 켜짐)**: 프로세스 우선순위 BelowNormal(`--prio -1`), 유휴 폴링 없음(`--poll 0`), 5분 유휴 시 모델 메모리에서 내림(`--sleep-idle-seconds 300`), 스레드 = 코어−1, 워밍업 생략.
- 시트릭스 정책 수치(CPU/메모리 상한)가 확인되면 `-Threads`, `-WatchInterval`, `-Latest` 로 맞춘다.

## 3. 파이프라인 규칙 (WPF 이식용 요약)

1. **배너 제거**: 앞 15줄 안에서 `보안 경고|외부에서 발송|열람 시 주의|악성코드|①②…|CAUTION|EXTERNAL` 줄 삭제
2. **인용 체인 절단**: 150자 이후 처음 나오는 `----- 원본 메시지 -----|_____|> ` 또는 헤더 줄(`From/Sent/Subject/보낸 사람/발신인/수신인/참조인/제목/날짜:` — 앞 공백 허용) 또는 `… wrote:` 에서 자름
3. **링크 → `[링크]`**, `<url>` 중복 제거, 공백 정리
4. **예산**(기본 900자) 초과 시: 앞 500자 + 날짜/까지/회신/제출/요청/비밀번호… 키워드 줄만 추려 붙임
5. **프롬프트**: 시스템(짧게, 오늘 날짜 포함) + 사용자(발신자·수신일·제목·본문). `enable_thinking:false`, temperature 0.1, max_tokens 180
6. **스키마**: `summary, action_items[], deadline|null, priority(enum), category(enum)` — llama.cpp `response_format: json_schema`
7. **후처리**: 할 일 중복·필드명 누출 제거·최대 3개 / 기한은 `YYYY-MM-DD` 정규화 → 수신일 이전이면 버림 → **본문에 해당 월일·상대 기한 표현이 없으면 버림**
8. **근거**: 슬롯 문장과 2-gram 겹침이 가장 큰 원문 문장(≥25%)
9. **캐시 키**: `모델|프롬프트버전|메일ID` — 규칙 바꾸면 버전을 올린다
10. **답장 초안**: 별도 프롬프트(정중한 업무체, 5문장, 없는 약속 금지) → 사용자가 편집 → 승인 → 메일 앱/회신 창
